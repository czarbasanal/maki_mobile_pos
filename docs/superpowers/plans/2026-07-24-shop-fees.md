# Shop Fees Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** First-class shop-fee lines (outside-item charges, electric charge, tire changer, air, …) on cart, job orders, and sales — with a managed catalog, management-side money routing, and their own EOD/report lines.

**Architecture:** `FeeLineEntity` mirrors `LaborLineEntity` through the whole stack (cart → draft → sale → summary → closing); the `shop_fees` catalog clones the mechanics data layer and the shared-list permission pattern; UI clones the labor section / list-editor patterns. Parts gross/net stay parts-only; fees are a third revenue track that automatically lands on management's side of the EOD handoff (which subtracts only labor).

**Tech Stack:** Flutter + Riverpod, Firestore (one new collection + rules block, NOT deployed in this plan), emulator rules suite.

**Spec:** `docs/superpowers/specs/2026-07-24-shop-fees-design.md`

## Global Constraints

- Branch: `feat/shop-fees` (created; spec committed).
- Money rule: fees belong to management; labor→mechanic routing unchanged; EOD handoff math (`countedCash − laborRevenue`) NEEDS NO CHANGE.
- Checkout rule (exact): checkout requires `items.isNotEmpty || feeLines.isNotEmpty`; labor alone remains blocked; existing labor validity rules unchanged (labor still requires fee > 0 per line; mechanic optional).
- Parts `grossAmount`/`netAmount`/`totalProfit` stay PARTS-ONLY everywhere. `grandTotal = partsRevenue + laborRevenue + feesTotal`. Fee lines are never discounted (like labor). Fees have zero cost (pure margin) but are NOT added to profit fields (report as own line only).
- `PostCloseActivity` is NOT changed (decided in planning): after-close fees ride the existing cash/sales-count deltas like labor does.
- Firestore: new `shop_fees` collection; rules block uses the 2026-07-24 shared-list pattern verbatim; **NO deploy in this plan**.
- Legacy tolerance: every reader defaults absent `feeLines` to `const []` and absent `feesRevenue` to `0`.
- Old plans' gotcha: a new gated MOBILE route needs `route_names.dart` (name + path) + `app_routes.dart` + `route_guards.dart` (`protectedRoutes`) — all three, or ProtectedRoute redirects.
- Tests mirror `lib/`; full `flutter test` + `flutter analyze` + rules suite in the final task.

Rules block (exact):

```
    // ==================== SHOP FEES COLLECTION ====================

    match /shop_fees/{feeId} {
      // Cashier-facing fee picker streams active fees — all-user read.
      allow read: if isValidUser() && isActiveUser();

      // Shared-list grants (2026-07-24): any active user may add or edit
      // entries; only staff/admin may flip isActive (deactivate/reactivate);
      // delete stays admin-only (nothing in-app hard-deletes).
      allow create: if isValidUser() && isActiveUser();
      allow update: if isValidUser() && isActiveUser() &&
        (isStaffOrAdmin() ||
          !request.resource.data.diff(resource.data).affectedKeys()
            .hasAny(['isActive']));
      allow delete: if isAdmin() && isActiveUser();
    }
```
