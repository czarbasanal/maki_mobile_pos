# JO Notes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Optional notes on Save-as-Job-Order (both surfaces), editable on the JO edit screens, carried onto the sale at bill-out on web (mobile already does).

**Architecture:** Mobile's notes pipeline (cart state → draft → sale) already exists — only inputs are missing. Web mirrors it by adding `notes` to the shared `createCartStore()` factory (covers both the POS cart store and the JO-edit store), threading it through `useSaveDraft` and `buildSaleInput`, and adding textareas.

**Tech Stack:** Flutter/Riverpod (mobile), React+Zustand+TanStack Query+Vitest (web).

## Global Constraints

- Empty/whitespace notes normalize to `null` — never empty string — at every write site.
- No Firestore rules/index changes; `drafts.notes` and `sales.notes` are existing schema fields.
- Spec: `docs/superpowers/specs/2026-07-27-jo-notes-design.md`.
- Web checks from `web_admin/`: `npm run typecheck`, `npm run test -- --run`. Mobile from repo root: `flutter analyze`, `flutter test`.
