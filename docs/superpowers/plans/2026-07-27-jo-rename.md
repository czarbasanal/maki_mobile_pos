# Drafts → Job Orders Rename + Schema Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename all job-order-concept "draft" terminology to "job order" across mobile, web, rules, indexes, and dev tooling, and ship the schema migration (`drafts`→`job_orders` collection, `sales.draftId`→`jobOrderId`) dark behind a user-triggered cutover runbook.

**Architecture:** Pure behavior-preserving renames per surface (existing 1601 flutter / 542 web tests are the harness), then additive rules/indexes (old + new live in parallel during transition), then an idempotent migration script. The authoritative symbol maps and do-NOT-rename collision list live in `docs/superpowers/specs/2026-07-27-jo-rename-design.md` — read it FIRST; every task below applies a subset of those maps.

**Tech Stack:** Dart/Flutter, TypeScript/React, Firestore rules/indexes, node scripts (firebase-admin).

## Global Constraints

- NO blanket `draft→jobOrder` replace. Compound symbols (`DraftEntity`, `draftId`, `useSaveDraft`, …) are renamed globally with word-boundary matches; BARE `draft`/`drafts` identifiers are renamed only inside JO-concept files (the spec's file lists), never in receiving/PO/EOD/payment/payslip files.
- Do-NOT-touch (spec "collisions"): `PurchaseOrderStatus.draft`+`isDraft`+`poDraft*`, `ReceivingStatus.draft`+`getDraftReceivings`+`draftReceivingsProvider`+`useDraftReceivings`+`resolveDraftItems`+`watchDrafts`+`receiving_drafts_screen`+`RoutePaths.receivingDrafts`+web literal `where('status','==','draft')`, `SaleStatus.draft`+`AppColors.draft`, `DailyClosingDraft*`, `PaymentDraft`/`usePaymentDraft`, `usePayslipDraft`, `PosPage.noteDraft`, `Icons.drafts`, web `routes.tsx` legacy `/drafts` redirect path literals, `docs/` + `design/` content.
- Persisted-name flips are exactly TWO constants: `FirestoreCollections.drafts → jobOrders = 'job_orders'` in `lib/core/constants/firestore_collections.dart:23` and `web_admin/src/infrastructure/firebase/collections.ts:16`.
- Transition read-fallback (temporary, dated TODO): mobile `sale_model.dart` map read `map['jobOrderId'] ?? map['draftId']`; web `saleConverter.ts` read `d.jobOrderId ?? d.draftId ?? null`. Writes use ONLY `jobOrderId`.
- End-of-task audit every time: `grep -rniE '\bdrafts?\b|draft' <changed area>` and justify every survivor against the do-NOT-touch list.
- NOTHING deploys in this plan. Rules/hosting/APK/migration are all steps of the user-triggered cutover runbook (spec §Cutover).
