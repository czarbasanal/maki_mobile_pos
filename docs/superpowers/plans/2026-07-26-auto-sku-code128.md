# Auto-SKU Code 128 Implementation Plan (P1)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** New auto-SKUs become `categoryCode(4)+sequence(4)` digits (Code 128-ready), with category codes assigned transactionally at creation, a read-only chip, peek-then-claim generation on mobile AND web, backfill, and CSV guardrails.

**Architecture:** Codes live in an immutable `category_codes/{code}` registry (created in the category-create tx; carries `nextSequence`). Product creation claims the final number inside the existing `product_skus` claim transaction with skip-and-retry. Old SKUs coexist; nothing is migrated. Spec: `docs/superpowers/specs/2026-07-26-auto-sku-code128-design.md`.

**Tech Stack:** Flutter/Riverpod + fake_cloud_firestore; web_admin React/TS/Vitest (vi.mock firestore template `FirestoreSaleRepository.test.ts`); Firestore rules emulator suite `tools/firestore-rules-test/`; Node ESM scripts.

## Global Constraints

- Branch `feat/auto-sku-code128` off main; one commit per task; TDD every task; `flutter analyze` clean; web `npm run typecheck` + `npm run test` clean (run inside `web_admin/`).
- Canonical SKU stored `00070153` (String, never parsed numerically). Display form `0007-0153` ONLY via the display helper. Mono font everywhere SKUs render (existing convention).
- Codes: 4 digits, start `0001`, monotonic, never reused/edited. Sequences: 4 digits, start `0001` per category; loud failure at 9999 ("Category is full — split it into two categories.").
- Auto-generation applies ONLY when a product category with a code is selected; no category selected → today's name-based generator stays as fallback.
- Recategorize never changes SKU (no code should ever rewrite `sku` on category change — verify nothing does).
- NO deploys, NO backfill execution in this plan — user-gated ship steps.
- Never `git add -A` (scripts/create-user.mjs, scripts/rename-product-category.mjs stay untracked).

```dart
// CategoryRepository:
Future<int> peekNextSequence(String categoryCode); // registry read; throws DatabaseException 'unknown-category-code' if absent
// ProductRepository.createProduct gains: String? autoSkuCategoryCode
```
Semantics inside `createProduct`'s EXISTING claim tx (all reads before writes — Firestore contract):
- `autoSkuCategoryCode == null` OR `!SkuGenerator.matchesAutoPattern(product.sku, code)` → manual path, byte-identical to today (claim check, DuplicateSkuException, counter untouched).
- Else: read registry; `candidate = max(sequenceOf(product.sku), registry.nextSequence)`; read claim for `composeAutoSku(code, candidate)`; while claimed → `candidate++`, read again (cap 25 iterations → `DatabaseException('sku-scan-exhausted')`); `candidate > 9999` → `ValidationException(code: 'category-full', message: 'Category is full — split it into two categories.')`. Writes: product with the FINAL sku, sku claim, barcode claims (unchanged), registry `nextSequence = candidate + 1` (targeted update of only that key).

  2. `00070001` pre-claimed (simulated race) + peeked `00070001` → saved `00070002`, `nextSequence == 3`.
  3. manual sku `BRAKE-99` with `autoSkuCategoryCode: '0007'` → saved as-is, `nextSequence` still 1.
  4. registry at `{nextSequence: 9999}` with `00079999` claimed → `category-full` ValidationException, nothing written.
  5. `peekNextSequence('0007') == 1`; unknown code throws.

### Task 7: Rules — category_codes + registry sequence updates

**Files:**

Rules block:
```
    match /category_codes/{code} {
      allow read: if isValidUser() && isActiveUser();
      // Created only alongside a product category (staff+admin, mirroring
      // product_categories create) — includes the '_counter' doc.
      allow create: if isStaffOrAdmin() && isActiveUser();
      // Registry docs: only nextSequence may change (product-create bumps).
      // '_counter': only next may change (category-create bumps).
      allow update: if isStaffOrAdmin() && isActiveUser() &&
        request.resource.data.diff(resource.data).affectedKeys()
          .hasOnly(code == '_counter' ? ['next'] : ['nextSequence']);
      allow delete: if false;
    }
```
